## 무엇을 세는가

- GT: TXT에 적힌 불꽃 정답 박스(클래스 1).
- TP: 예측 fire 박스와 정답 fire 박스가 IoU 0.5 이상으로 일대일 연결됨.
- FN: 연결되지 않은 불꽃 정답 박스. 한 이미지의 일부 불꽃만 놓쳐도 해당 박스는 미탐이다.
- FP: 정답과 연결되지 않은 fire 예측 박스. 배경 오탐 외에 중복 검출/부정확한 위치도 포함된다.
- 낮은 confidence 후보를 한 번 수집하고 0.10/0.15/0.20/0.25/0.35/0.50 조건을 비교한다.

이 계산은 고정 confidence의 별도 오류 분석이다. Ultralytics val 출력의 최적 F1 기준 P/R 및 mAP와 같은 지표라고 해석하면 안 된다. 기존 test fire recall 0.625를 그대로 'conf 0.25에서 37.5% 놓침'이라고 환산하지 않는다.

## 산출물

Drive의 기존 실행 폴더 아래 `analysis/fire_fn_val_날짜_고유ID/`에 새 폴더가 생긴다. 모델/라벨/원본 ZIP/기존 평가 파일을 덮어쓰지 않는다. Drive에는 모델과 전체 데이터 사본을 추가하지 않고 결과 파일과 예시 사진 최대 30장만 저장한다.

- `threshold_sweep.csv`: 기준별 fire TP/FP/FN, P/R, 불꽃 전체를 놓친 이미지 수, 불꽃 없는 이미지에서 오탐한 이미지 수.
- `fire_missed_boxes.csv`: conf 0.25에서 놓친 모든 불꽃 정답 박스와 검토 힌트.
- `examples/`: seed 42로 고른 미탐 이미지 최대 30장. 빨강은 놓친 fire 정답, 초록은 매칭된 정답, 파랑은 fire 예측, 노랑은 smoke 예측.
- `predictions.jsonl`: 전체 val의 정답 fire 좌표와 conf 0.05 이상 예측. 검토용이며 재학습 데이터로 자동 사용하지 않는다.
- `summary.json`: 모델/분할 해시, 분석 조건, 집계 결과.

## 결과를 보고 할 일

1. 기준 0.25 대비 0.20 또는 0.15에서 FN이 얼마나 줄고 FP가 얼마나 늘었는지 함께 본다. 숫자를 보기 전에는 기준을 자동으로 낮추지 않는다.
2. `low_confidence_candidate`는 위치가 맞는 낮은 점수 fire 후보가 있어 기준 조정이 도움될 수 있다는 단서다. 실제로 해당 박스가 회복되는지는 threshold 표/매칭 결과로 판단한다.
3. `smoke_overlap_review`는 smoke 예측과 겹쳤다는 뜻이다. 불꽃과 연기가 실제로 겹칠 수 있으므로 'fire를 smoke로 잘못 분류했다'고 단정하지 않는다.
4. 작은 불꽃, 야간, 가림, 박스 위치, 라벨 상태를 사람이 확인하고 원인을 분류한다.
5. 재학습이 필요하면 train 쪽 유사 사례 라벨 QA/추가 자료/해상도 등으로 새 실험을 만든다. val/test를 train으로 옮기지 않는다. 기존 모델은 기준 모델로 유지한다.

test는 이미 확인했으므로 기존 test 결과는 기준 기록으로 남긴다. 개선 설정은 val에서 결정하되, 개선 모델의 최종 일반화 성능 주장은 새로운 미사용 평가 자료로 확인하는 것이 좋다. 이번 작업은 미탐을 자동으로 고쳤거나 최종 성능이 향상되었다는 증거가 아니다.

## 확인 범위

분석 코드와 노트북을 준비하고 로컬 자동 테스트로 매칭·보고서 저장·미탐 시각화 경로를 확인했다. 전체 자동 테스트 27개 통과(새 분석 관련 9개 포함). 실제 선정된 best.pt로 합성 이미지 2장에 CPU 추론하여 코드 호환성과 예시 이미지 저장도 확인했다. 이 합성 자료 검사는 성능 평가가 아니다. 검사 전후 원래 모델 SHA256은 동일했다.

Colab 전체 val 실행은 아직 하지 않았다. 사용자가 실행해야 하며, 해당 실행 전에는 실제 미탐 개수나 개선 폭을 알 수 없다.

참고: [D-Fire 공식 저장소](https://github.com/gaia-solutions-on-demand/DFireDataset), [Ultralytics predict 문서](https://docs.ultralytics.com/modes/predict/). confidence는 예측 보존 기준이고, 코드의 `iou=0.7`은 NMS 기준이다. 별도의 `MATCH_IOU=0.5`가 정답-예측 매칭 기준이다.
