# 불꽃 오탐 억제 작업 결과 — 2026-10-05

## 결론

기존 YOLO11n 70epoch 모델을 재학습하지 않고, 예측 뒤에 적용하는 보수적인 필터를 추가했다. validation 전체 3,445장을 로컬 CPU에서 새로 추론해 비교했을 때 **불꽃 박스 오탐 870 → 738개(15.2% 감소)**, 미탐 639 → 638개였다.

다만 **불꽃 정답이 없는 이미지의 잘못된 감지 34장은 그대로**다. 중복·위치 오류를 포함한 박스 오탐 감소이지, 실제 CCTV의 잘못된 화재 경보가 15.2% 감소했다는 뜻은 아니다. 미탐도 크게 해결된 상태는 아니다.

## 실제 변경 및 실행

- 새 필터: `scripts/fire_policy.py`, 설정: `configs/fire_policy_v1.json`.
- 새 이미지 실행: `scripts/infer_fire_frame.py`. 필터 후 사진과 JSON을 함께 저장한다.
- 비교 도구: `scripts/tune_fire_policy.py`, `scripts/compare_fire_resolution.py`, `scripts/audit_policy_changes.py`.
- 기존 모델, 학습 노트북의 사용자 실행 결과, 원본 데이터 ZIP은 덮어쓰지 않았다. MP4 처리와 추가 학습은 하지 않았다.
- 기존 `infer_media.py`나 학습 노트북을 실행한다고 새 필터가 자동 적용되지는 않는다. 새 이미지 실행 코드를 사용해야 한다.

적용 방법과 Colab 복사·실행 셀은 [FIRE_POLICY_USAGE.md](../FIRE_POLICY_USAGE.md)에 있다. 팀원은 자신의 PC 이미지 경로를 사용하거나, 준비된 Colab validation 이미지로 실행하면 된다. 다시 70epoch 학습할 필요는 없다.

## 동일 CPU 실행에서의 전후 비교

불꽃 정답 박스 2,154개, 불꽃이 있는 이미지 888장, 불꽃 정답이 없는 이미지 2,557장이다. 박스 일치 기준은 IoU 0.5, confidence 순서의 일대일 매칭이다. 표는 fire 클래스만 평가한 것으로 smoke 성능 개선을 주장하지 않는다.

| 지표 | 기존 640 / conf 0.25 | 새 640 필터 |
| --- | ---: | ---: |
| 정답과 맞은 불꽃 박스 TP | 1,515 | 1,516 |
| 잘못된 불꽃 박스 FP | 870 | 738 |
| 놓친 불꽃 박스 FN | 639 | 638 |
| 박스 precision | 63.52% | 67.26% |
| 박스 recall | 70.33% | 70.38% |
| 불꽃 있는 이미지에서 fire 후보가 하나라도 나온 이미지 | 855 | 855 |
| 불꽃 있는 이미지에서 fire 후보가 전혀 없는 이미지 | 33 | 33 |
| 불꽃 없는 이미지에서 fire 후보가 나온 이미지 | 34 | 34 |
| 기존에 후보가 있던 이미지 중 새로 후보가 사라진 이미지 | 해당 없음 | 0 |

이미지 후보 유무 지표는 박스가 실제 불꽃 위치에 맞았는지와 무관하다. 이를 화재 사건 탐지율이나 모델 전체 정확도로 해석하면 안 된다. precision 67.26% 역시 위 조건에서의 불꽃 박스 precision이지 이미지 정확도가 아니다.

이전에 저장된 Colab 예측에서는 TP 1,514 / FP 870 / FN 640이었고 필터 후 TP 1,516 / FP 738 / FN 638이었다. 장치·패키지·배치의 수치 차이로 CPU와 Colab의 일부 경계 박스가 달라질 수 있다. **한 비교 안에서는 같은 실행의 전후 수치만 사용했다.**

## 선택한 조건

1. 기존 YOLO 예측 후보를 `imgsz=640`, `rect=False`, `conf=0.05`, `iou=0.7`, `max_det=300`으로 수집한다.
2. fire 점수가 0.25 이상인 후보를 유지한다.
3. fire 점수가 0.22 이상 0.25 미만인 후보는 0.25 이상의 fire 후보가 근처에 있을 때만 추가한다. 중심 간 x/y 거리를 이미지 너비/높이로 정규화한 거리 기준 0.4다.
4. fire끼리 높은 점수 우선으로 추가 중복 제거(IoU 0.45)를 적용한다. 이는 원래 YOLO NMS를 0.45로 바꾸는 것과 다른 두 단계 처리다.
5. smoke 기준은 기존 0.25를 유지한다. smoke만 보고 fire 박스를 새로 만들지 않는다.

낮은 점수 fire만 있는 이미지에서는 새 경보를 만들지 않는 구조다. 그 대신 불꽃 없는 장면의 기존 강한 오탐까지 없애는 필터는 아니다.

## 비교했지만 채택하지 않은 방법

confidence를 0.5로 올리면 같은 CPU 640 예측에서 박스 오탐은 205개로 줄지만 미탐은 1,094개로 늘었다. 불꽃을 더 많이 놓치는 방식이라 채택하지 않았다. 이번 선택은 **미탐 총수와 기존에 감지된 이미지 유지를 안전 조건으로 두고 오탐을 줄인 것**이지, 가능한 모든 방법 중 절대 최소 오탐이라는 주장이 아니다.

전체 validation에서 입력 해상도 960도 실제로 비교했다.

| 같은 CPU / conf 0.25 | 640 | 960 |
| --- | ---: | ---: |
| 불꽃 TP | 1,515 | 1,537 |
| 불꽃 FP | 870 | 1,009 |
| 불꽃 FN | 639 | 617 |
| 전체 추론 실행 시간 | 약 134초 | 약 240초 |

960은 미탐 22개를 줄였지만 오탐이 139개 늘고 실행 시간이 약 1.78배였다. fire 근접 조건, 추가 중복 제거, 실험적인 smoke 지원 조건을 포함해 프로파일별 309개 후보를 비교했다. 960에서는 정한 안전 조건을 모두 만족하는 개선을 찾지 못해 최종 채택하지 않았다.

## 검증 범위와 원본 보호

- 학습 모델 SHA-256: `57c133a489976dc2f7341381b12cf160622e0bbaff33aeffdee4926e2093611d`.
- 기존 저장 validation, 새 CPU 640/960 전체 validation을 사용했다. test를 다시 실행하거나 test 점수로 조건을 고르지 않았다.
- 내부 calibration/audit는 이미지 단위로 70/30 분할했지만, 이미 검토한 validation을 반복 사용한 개발 실험이다. 후보 확장 과정에서도 내부 audit가 재사용됐고 카메라·사건별 분할이 아니므로 독립 최종 평가라고 주장하지 않는다.
- 원본 ZIP을 읽어서 validation 3,445장만 `C:\fire-ai-local\data\val_resolution_20261005_crc`에 별도 준비했다. 원본 ZIP은 읽기 전용으로 사용했다. 로컬 사본의 JPEG 복구가 필요한 경우에만 해당 사본을 수정했다.
- 추출 항목은 ZIP CRC 읽기 검증, 기존 manifest와 정규화 라벨 SHA 비교, 이미지 크기·정답 좌표 비교를 수행했다. Drive 스트리밍 지연 때문에 **원본 전체 ZIP의 SHA를 이번에 새로 끝까지 검증한 것은 아니다.**
- 실제 `infer_fire_frame.py`로 원본 AoF04266 이미지 사본을 처리해 필터 후 사진과 JSON 생성도 확인했다.
- 최종 자동 테스트 35개가 모두 통과했다. 낮은 점수 fire 단독 경보 금지, 클래스별 중복 제거, 기존 감지 이미지 손실 거부 등을 포함한다.

원시 CPU 비교 기록은 `C:\fire-ai-local\runs\resolution_full_20261005`에 있으며, 주요 수치와 출처 해시는 [comparison.json](comparison.json)에 보관했다. 최종 설정 사본은 [fire_policy_v1.json](fire_policy_v1.json)이다.

## 아직 남은 문제

불꽃 없는 이미지의 잘못된 감지 34장과 작은 불꽃·위치 불일치 미탐은 남았다. 이를 추가로 해결하려면 실제 사용 카메라의 불꽃 없는 프레임으로 오탐 유형을 검토하고, 학습용 hard-negative/작은 불꽃 데이터를 구성한 뒤 별도 검증이 필요하다. 이번에는 원본 라벨을 임의로 바꾸거나 재학습·API 연동·실제 경보 운영까지 진행하지 않았다.
